## PROJECT DATA IS STORED TWICE. KEEP BOTH IN SYNC.

This is the single most important rule in this file. Project content lives in two places:

1. `projects.html`: one `<li class="project-item">` per project. **This is canonical.** `node scripts/build.js` parses it into `data.json`, `llms.txt`, `llms-full.txt` and `sitemap.xml`.
2. `work/index.html`: a `<script type="application/json" id="projects-data">` blob that the short page's detail panels read.

**Any edit to a project must be applied to both, in the same change.** Never update one and leave the other. Letting them drift has already produced live contradictions: the MCP server said 13 tools in one place and 17 in the other, GitTrack said 1000+ jobs in one and 3000+ in the other, and AudiTex had a GitHub link on one endpoint only.

The two copies are allowed to differ in **length and tone only**. The short page is terse for recruiters, the long site tells the story. Every fact, number, date and link must match exactly.

After any content edit: run `node scripts/build.js` and commit the regenerated outputs.

To check for drift, parse both and compare `date`, `links`, and any number that appears in each.

## Writing conventions for this site

- **No em dashes.** Not `—`, not `&mdash;`. Use a comma, or split the sentence. The user is firm on this.
- Essays carry a style map in their markdown source. A line tagged `<!-- punchline -->` becomes `<p class="punchline">`: standalone, 18px, extra air above and below. `*italic*` is `<em>`, never bold. Double quotes stay plain, no blockquotes.
- Taglines must not restate the first line of the description.
- Keep project descriptions short on the short page. The user's words: recruiters "really don't give a fuck" about stories.
- Only link things that are verified. Check the URL returns 200 before linking it.

## Skills section

`work/index.html` only, never the long site. It sits between Experience and Selected work: twelve core chips always visible, then a toggle that reveals all 120 skills as group cards (`.sk-all`, CSS columns so the cards pack without holes). Every skill is in the DOM at load, the toggle only flips `hidden`, so keyword scans and crawlers see the full list.

The same list is machine-tagged twice in the head of that page: a `<meta name="keywords">` and a `Person` JSON-LD with `knowsAbout`. All three copies must carry the same skills, so regenerate them together.

Agentic AI and LLM engineering lead on purpose, both in the core chips and as the first two cards. That is the attention the user wants drawn. Everything else follows the resume's grouping.

## Conventions

- User writes in caveman-terse mode requests; keep replies short. Screenshots via headless Chrome (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=new --screenshot=… --window-size=1400,900 --virtual-time-budget=3000 <url>`) work well for checking layout; use `?xp=` / `?p=` to capture open states.
- `sips` is available for image crops (no PIL installed).
- **Headless Chrome on macOS clamps its viewport to ~485 CSS px**, whatever `--window-size` says. A narrower `--window-size` just crops the image, so the page looks like it overflows when it does not. To check mobile layout for real, load the page in an `<iframe>` of the target width inside a wider wrapper page and compare `documentElement.scrollWidth` with `clientWidth`. The short page was verified clean at 360px and 390px this way.
- Commit messages end with `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
